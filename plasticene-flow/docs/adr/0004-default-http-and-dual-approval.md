# 提供正式默认 HTTP 接口并支持两种申请方式

2026-11-16 确认：FLOW 的默认 HTTP 接口是可直接复用的正式接口，不再仅定位为参考示例；宿主仍可按需自行接入。这调整了 ADR 0003 中 Web 的示例定位，意味着默认接口的契约与行为需要作为受支持能力维护。

FLOW 同时正式支持关联宿主业务单据的审批和通过自带表单发起的独立申请。业务单据及其修改入口归宿主管理，FLOW 保存业务关联、审批所需变量及必要快照；自带表单申请的数据由 FLOW 管理，不要求业务单据复制为 FLOW 表单。

宿主复用自身的权限体系决定管理能力授权，FLOW 负责审批规则和组织隔离，不另建完整的角色授权体系。保留模型管理员作为具体模型的管理范围约束，与宿主授予的功能权限共同生效。Java 与 HTTP 调用均通过统一用例边界执行宿主授权检查；公开接口按职责拆分，不强求统一的 FlowEngine 入口。具体接口清单、扩展点和模块内部边界仍在讨论，本决策不批准具体代码重构。

审批变量定义与表单配置分离：条件配置依赖变量字段及类型契约，自带表单提供对应字段信息，业务单据方式由宿主提供。运行实例使用 FLOW 已保存的审批数据，宿主业务单据修改不自动同步；影响审批的关键字段变化由宿主限制修改，或取消旧申请后重新发起。审批中已有的显式表单编辑能力仍须遵守字段权限并记录变更。

对外扩展通过明确的 SPI 提供组织人员、审批人解析、通知和业务事件接收等能力；不将执行内核替换作为受支持的扩展方式，节点推进和任务生命周期由 FLOW 统一保证。宿主提供业务单据详情，FLOW 提供可复用的审批区域；独立表单申请展示 FLOW 表单并复用同一审批区域，不要求宿主将业务详情转换为统一页面数据协议。具体前端组合方式尚待设计。

流程模型明确区分业务单据审批和独立表单申请，申请方式随发布定义保留，运行实例遵守对应发布版本的方式；不在发起时仅凭 businessId 是否为空临时选择方式。两种方式共用执行内核。此区分独立于 Java 或 HTTP 接入方式。

业务单据审批的变量契约由宿主管理，流程管理员使用其字段配置条件，不自行改变宿主字段契约；独立表单申请从表单字段获得变量定义。发布时保存变量定义，运行时按照实例绑定的发布版本校验输入，不使用宿主最新契约替换历史版本。

Q14 已确认整体分层方向。补充要求：超时相关自动配置由一个配置类集中管理。Q15、Q16 已确认：FLOW 提供纯基线与版本增量 SQL，由宿主数据库发布流程执行，Starter 默认不自动改表；REST 模块更名为 plasticene-flow-rest，移除平台 Web Starter 的直接依赖，由宿主显式引入并统一版本。具体接口签名、兼容处理和迁移步骤见完整改造方案，尚未授权代码实施。

存量事实澄清：用户确认目前无外部真实 API 调用、无服务引用框架，现存历史全为 FLOW 自带表单，每个发布定义只使用一种申请方式。据此改造方案不再设计外部兼容期或混用历史过渡；存量迁移只补新增申请方式与发布变量定义元数据，具体实现仍待确认。

字段命名确认：表单类型字段使用 form_mode，发布时变量定义信息字段使用 var_info；仅调整命名，不改变两种表单类型及变量定义版本快照的职责。

表单类型切换规则确认：模型设计态允许切换表单类型；保存设计态不影响当前生效版本，重新发布后对新申请生效。历史发布定义和运行实例保留原 form_mode、form_config 与 var_info；同一模型不同版本类型不同属于正常版本演进，不视为混用历史。

实施授权及测试依赖确认：用户已确认按更新后的完整方案实施前后端、SQL 与测试，不自动提交；另单独确认 plasticene-flow-rest 可在 scope=test 声明 spring-boot-starter-web，版本沿用父 POM，仅用于 Servlet/MVC 测试，不作为运行时传递依赖。
