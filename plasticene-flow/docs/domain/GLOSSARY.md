# 业务审批

审批支持关联宿主业务单据的申请，以及使用自带表单的独立申请。业务审批的结果由宿主用于处理对应业务单据。

## 术语

**表单类型**：审批申请使用的表单形式，分为 FLOW 自带表单与宿主业务表单。设计态可切换，重新发布后对新申请生效，已有审批过程保持原类型。

**业务单据审批**：关联宿主业务单据的审批方式，业务单据及其修改由宿主管理。

**独立表单申请**：通过 FLOW 自带表单提交的申请，申请数据由 FLOW 管理，不要求关联宿主业务单据。

**请假单**：员工提出的请假业务单据，审批通过且业务处理成功后生效。

**申请记录**：一次业务申请的记录，与一个流程实例一对一。拒绝后重新申请须创建新的申请记录。

**流程实例**：一次流程从发起到结束的审批过程；业务单据审批与一条业务申请记录一对一，独立表单申请不要求关联宿主业务单据。

**审批变量定义**：流程可使用的变量字段及其类型约定，供审批条件配置与数据校验使用，不包含表单控件和布局。

**审批数据**：流程实例内保存、用于审批判断的数据；宿主业务单据的修改不会自动改变这些数据。

**表单配置**：独立表单申请所使用的字段控件、布局及交互配置，与审批变量定义职责不同。

**流程编码**：标识一种流程的稳定业务标识，发布新版本不改变该标识。

**流程分类（业务类型）**：业务审批所属的业务种类，以分类编码标识，并用于将流程事件交给对应业务接收方；不另设独立的业务类型概念。

**事件交付成功**：业务事件接收接口正常返回，表示业务已接收该流程事件；不表示业务单据已生效或用户通知已发送。

**申请人**：提交请假申请的员工，也是审批通过消息的接收人。

**审批人**：负责审核申请的人；请假试点中由部门负责人担任。

**退回**：将当前审批任务退至流程有效执行路径上已完成的前序人工审批节点，流程继续审批。不包含退回申请人修改业务单据。

**拒绝**：使当前流程以不通过的结果结束。申请人需要修改申请时，可修改业务单据后重新发起流程。

**撤回**：审批人按既有规则撤销自己已同意的审批结果，使对应审批任务恢复为待办理；不等同于申请人取消申请。
